# 客戶第一次諮詢問卷 — 規格拆解

**來源**：教練實際使用中的 SurveyCake 線上表單「財務教練第一次諮詢問卷（版本 25.8.14）」
**填寫者**：⚠️ **教練**，不是客戶。教練在諮詢現場開著它，一邊詢問客戶一邊填。
**樣本**：一份完整填答（22 頁，填答耗時 **4927 秒 ＝ 82 分鐘**＝一場諮詢的實際長度）
**拆解日期**：2026/08/25
**用途**：這份是「教練說的表單」的實體。拿來對照嵐途現有欄位、找出缺口與動線差異。

> ⚠️ 本文件只記錄**結構**，不含任何客戶的實際答案。

---

## 零、這份東西到底是什麼

**它是「一場諮詢」的紙本版——一份逐題腳本。**

教練在客戶面前開著它，照著從第一題問到最後一題，82 分鐘問完。問完的同時就得到：完整的客戶資料、每個面向的重要程度、每段的特別註記、以及收尾的心得。

這個前提決定了後面所有的解讀，所以先把每個欄位的真實意義釘住：

| 欄位 | 真實意義 | 嵐途對應 |
|---|---|---|
| 各段的「特別註記」 | 教練現場聽到客戶講的話，**當場打下來** | 區塊註記（`kind='basis'`／`'decision'`） |
| 「是否有待補件資訊」 | 問到一半發現客戶沒帶勞健保、保單，當場記下 | 區塊註記（`kind='todo'`）→ `action_items` |
| 「總結、此次諮詢的心得體驗」 | 收尾時談完的總結 | 諮詢摘要（`reviews.summary`） |
| 填答秒數 4927 | **一場諮詢的長度** | `consult_sessions` 的 started/ended |
| 「重要程度」⭐ | 資源不足時的取捨依據 | `imp` |

→ **零件幾乎全部對得上。** 我們 2026/08/25 做的「一場諮詢 ＋ 區塊註記」與這份問卷是同一件事的兩種載體。

### ⚠️ 但我們缺了最關鍵的一半：問題本身

| | SurveyCake 問卷 | 嵐途的註記 |
|---|---|---|
| 性質 | **主動** — 推著你走完 11 個面向 | **被動** — 想到才寫 |
| 保證 | 走完＝問完，不會漏 | 沒有這個保證 |
| 現場可用性 | 一頁一段，邊講邊打 | 密集表格，要先找到欄位 |

**教練懷念的不是「表單」這個載體，是「照著問就不會漏」，以及在客戶面前打字時的順手。**

### ⚠️⚠️ 真正的痛點：雙重工

教練現在必須**同時開兩個東西**——用 SurveyCake 問，回頭再把資料謄進嵐途。

所以他問的「未來是不是也有類似的工具，還是要直接用系統做記錄」，
真正的意思是：**「我可以只開一個嗎？」**

這是雙重工的問題，不是功能請求。

## 一、⭐ 最重要的發現：問卷的骨架跟我們做的註記是同一個形狀

問卷把人生拆成 11 個規劃面向，而**每一個面向的結尾都固定問兩題**：

```
（該面向的所有欄位…）
  ↓
「於你而言 ○○ 的重要程度為何？」   → 星等 1–5 ⭐
「特別註記」                        → 自由文字
```

**「每一段結尾寫一句自由文字」本來就是教練工作流裡既有的動作。**

我們做的區塊註記不是新發明，是把他紙上的習慣搬進系統。這是對那個設計最強的驗證——也代表教練會填，因為他本來就在填。

**同時這也解釋了他為什麼會問**：他熟悉的工具長這樣，而他在系統裡沒看到對應的東西（註記剛上線，他大概還沒看到）。

## 二、問卷的三層結構，跟系統資料模型完全對得起來

問卷對每一個目標都問三種東西，剛好就是系統既有的三層：

| 問卷的問法 | 系統欄位 | 語意 |
|---|---|---|
| 「你認為哪些願景是人生中『**一定**』要實現的」 | `on`（願景選定閘） | 要不要做 |
| 「預期購車預算多少？」／「預期**最低**預算為多少？」 | `present` / `minPresent` | 理想 vs 可壓縮到的底線 |
| 「於你而言○○的重要程度」⭐ | `imp` | 資源不足時的取捨依據 |

**三層的順序也一致**：先選定 → 再給理想與底線 → 再給重要度。

這代表系統的資料模型跟教練的方法論是同一套，不是各長各的。**動這三層之前，記得它們在紙上也有對應物。**

## 四、系統缺的東西（問卷有、嵐途沒有）

按「值不值得補」排序：

### 高價值

1. ⭐ **「若給你一年時間挑戰收入上限，可達到多少月收入？」**
   這是**收入的彈性上限**，而系統的六根槓桿裡沒有這個。目前調高收入是教練自己抓一個數字，這題等於讓客戶自己給出上界——是缺口求解器可以直接吃的參數。

2. ⭐ **逐項支出的「可刪減或調整的空間」**
   系統有 `cut`（可壓縮%）但躲在支出列的進階欄，實務上是**教練自己憑經驗抓一個數字**。問卷則是**當著客戶的面逐項問過去**。差別在於：客戶自己親口說可以砍的，跟教練替他假設可以砍的，之後拿出來談的說服力完全不同。

3. ⭐ **「你認為身上有多少可動用資金，才有足夠的安全感？」**
   系統的緊急預備金是算的（`emergencyMonths` × 月支出）。這題問的是**心理安全感**，兩個數字常常差很多——而客戶只會照自己那個數字行動。

4. **每類資產的「是否可以進行變動？」**
   系統有 `movable` 但只是一個 checkbox。問卷把它變成每一類資產都要回答的必答題，而且配一句文字說明狀況。

5. **健保三欄**（投保類別／月投保薪資／負擔眷屬人數）
   系統只有勞保那組。健保這組是實際保費與眷屬負擔的依據。

### 中價值

6. **休閒興趣六分類 ／ 奢侈品十六分類**
   系統的 `lifestyle` 只有旅遊／休閒／奢侈品三張表，每張自由填。問卷把它結構化成分類清單——好處是**不會漏問**，壞處是欄位爆炸。

7. **子女的結婚／買車／買房／創業準備基金**
   系統的 `c.education[]` 只算教育。這幾筆是「給子女的」而不是「養子女的」，在現金流上是不同性質的支出。

8. **信用的七項行為指標**
   系統只存一個分數。問卷問的是行為（準時繳款／分期／不良紀錄／近三月辦卡），那才是分數的成因。

9. **「待補件資訊」**
   系統的「資料檢核表」有類似的東西，但問卷是**問到一半發現客戶沒帶什麼，當場勾起來**。
   → 這其實就是 `kind='todo'` 的註記，只差一個「常見待補項目」的勾選清單。

### 需要判斷

10. **「總結、此次諮詢的心得體驗」**
    收尾時打的一整段。系統的諮詢摘要目前是**由註記自動聚合**產生的，沒有這種「自己從頭寫一段」的欄位。
    兩者不衝突：自動聚合負責不漏，自由書寫負責講出那些不屬於任何單一區塊的話。
    ⚠️ 若它會印進客戶報告書，要走「客戶可見」那條合規線。

## 五、系統有、問卷沒有的（互補關係）

- 完整的資產負債表逐筆金額（問卷只問「狀況」用文字描述）
- 保單逐張登錄與五欄比對
- 現金流投影、`shortPV` 缺口計算
- 24 項財務比率體檢
- 調整方案與動作清單

**→ 兩者是互補不是取代**：問卷負責「把客戶腦中的願景與現況問出來」，系統負責「算」。

**而這正是雙重工的來源**——教練必須先用問卷問完，再把同一批資料謄進系統算。
解法不是二選一，是**把問卷的「問法」搬進系統**，讓同一次輸入同時完成兩件事。這就是第七節的訪談模式。

## 六、動線差異（這才是教練真正感覺到的落差）

| | 問卷 | 嵐途現況 |
|---|---|---|
| 組織方式 | **按人生面向**逐一問完 | 按**資料類型**分 18 個分頁 |
| 順序 | 固定，照著走 | 自由跳轉 |
| 完成度 | 走完＝問完 | 有完整度列，但不是一條路 |
| 誰填 | **教練在現場邊問邊打**（82 分鐘） | 教練，但是在工作台上找欄位 |
| 結尾 | 每段都有 ⭐重要程度 ＋ 特別註記 | 註記剛上線 |

**教練懷念的不是「表單」這個載體，是「照著走就不會漏」這件事。**

系統目前沒有這條線——它是一個工作台，不是一份問卷。

## 七、我押的方向：訪談模式

**不是新的資料結構，是既有欄位的另一種呈現順序。**

系統已經有這份問卷九成的欄位。缺的只是一層外殼：

```
按「開始諮詢」
   ↓
進入訪談模式：照 11 個面向逐段呈現，一次只給一段，大字好打
   ↓
每段結尾＝既有的 重要程度⭐ ＋ 註記（本來就有了）
   ↓
走完 → 結束諮詢 → 產摘要（本來就有了）
```

**它跟 2026/08/25 上線的「一場諮詢」天然接得起來**——那個容器已經在了，訪談模式只是給它一條路。做完之後 SurveyCake 可以退場，教練只要開一個。

### 驗收基準：82 分鐘

這是現成的、真實的基準。**訪談模式如果走不完在 82 分鐘內，就是失敗的**——教練會退回去用 SurveyCake。

這條基準也順帶決定了幾件事：
- 不能每一題都要捲動去找欄位 → 一段一頁
- 不能要求先切分頁再填 → 訪談模式自己決定順序
- 打字不能被 render 打斷 → 沿用 `setLive`／`LN.typing` 那條路
