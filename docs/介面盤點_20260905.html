看起來全部黏在一起，是因為整套系統只用一種 1px 半透明線在分隔所有東西

這輪不動任何功能，只用教練的眼睛從頭走一遍：官網、教練端、規劃器、客戶端、後台。49 項發現，全部收斂成三條根因——沒有色彩 token 層、沒有共用版面殼、沒有層次（elevation）。第三條就是「黏在一起」的直接答案：全站 3,162 處寫死的色碼撐起來的畫面，分隔手段只有 border-white/10 這一招，卡片、清單列、統計磚、彈窗長得一模一樣。順帶把淺色版的 9 顆地雷先挖出來——那不是把顏色反過來就能做的事。

根因 A

沒有 token 層，顏色是每次手打的

Next 端 2,565 處、規劃器 597 處，103 個不同 hex。同一個「次要說明文字」有 #a9bccf 和 #a7bacb 兩種；同一個「輸入框底色」有 #0a1a2b 和 #0a1a28——差一個字元，肉眼分不出來，卻是兩份要各自維護的字串。這就是淺色版做不出來的原因。

根因 B

沒有共用版面殼，每頁自己刻一遍

/dashboard 和 /portal 底下都沒有 layout.tsx，頂欄靠每支 page 自己 import。漏掉的三頁（我的業務／我的公開檔案／業務制度說明）整條導覽列直接消失。後台則是 11 份逐字複製的 header。容器寬度全站 8 種。

根因 C

只有 1px 線在分隔，沒有層次

教練端全部 118 支 tsx 只出現 3 次 shadow，規劃器表格儲存格 padding 只有 6px 7px，後台表格沒有一張有 zebra 或 hover。卡片、清單列、統計磚、空狀態共用同一組 class——所有東西都停在同一個平面上。

E · 跨畫面的一致性

9 項

這一節不屬於任何單一畫面，但它們是「整體看起來不精緻」的累積來源。

天天卡到E1

全站只有 3 次陰影，所有東西停在同一個平面上

118 支 tsx 裡 shadow 只出現三次（其中兩次在彈窗）。卡片、清單列、按鈕、彈窗之間唯一的區隔手段是 1px 的 border-white/10~15，共 448 處。這就是「全部黏在一起」最直接的成因——不是間距不夠，是沒有第二種分隔語言。

border-white/N：448 處　　shadow：3 處（shadow×1、shadow-2xl×1、shadow-[0_18px_50px…]×1）

導入三階層次：底層（頁面底色）／面板（底色差一階，無邊框）／浮起（有陰影）。邊框只留給需要圈住的東西，不要當萬用分隔線。

天天卡到E2

26 種字級，其中 text-[11px] 用了 115 次、text-xs（12px）用了 139 次

兩套系統並存：Tailwind 具名尺寸和手打的 arbitrary px。text-[12px]、text-[12.5px]、text-[13px]、text-[13.5px] 四個差不到 1.5px 的尺寸同時活著，光 ClientDetail.tsx 一支檔案就同時用了 10/11/11.5/12/12.5/13 六種。這些差異在螢幕上根本看不出來，純粹是每次手打造成的漂移。

text-sm 234・text-xs 139・text-[11px] 115・text-[12px] 58・text-[13px] 48・text-[12.5px] 33・text-[11.5px] 22 …（共 26 種）

定 6 階並全域取代；半像素階一律併掉。

天天卡到E3

最常用的說明文字顏色對比只有 3.8:1，而且多半是 11px 小字

#6f869c 在 #0d2b45 上約 3.83:1、在 #12334f 上約 3.45:1，都低於 WCAG AA 的 4.5:1；而它幾乎都搭配 11–12px（不屬於「大字」的放寬標準）。它偏偏是全站最常見的「為什麼要這樣填」「注意事項」用色——也就是最需要被讀到的那些字。

大量出現於 HomeView / PassportWizard / ProfileEditor / SetupWizard 等數十處

次要文字提到 #8fa6ba 一階（約 5.2:1），三級文字才用現在這個亮度。淺色版要另外定，不能沿用。

明顯不一致E4

金色同時是品牌色、選取狀態、和警示色

額度快滿、草稿未存、護照過期都用 #c99a5b 淡底加邊框——和「這是主要按鈕」「這個頁籤被選中」用同一個顏色。使用者看到金色時無法判斷這是「重點」還是「要注意的問題」。

ClientList.tsx:93-96 額度快滿　ClientDetail.tsx:503 草稿提醒　PassportWizard.tsx:278 護照過期

警示改用獨立的琥珀／橘色階，金色只留給品牌與選取。

明顯不一致E5

錯誤訊息有四種長相，其中一種還是橘色的

純文字紅、徽章式紅、深酒紅滿版 banner、以及橘色純文字——同樣是「這個動作失敗了」。橘色那組容易被讀成「警示」而不是「錯誤」。而紅色徽章又同時代表「額度已滿（危險）」和「授權過期唯讀（狀態）」兩種嚴重程度完全不同的事。

① SetupWizard.tsx:110,120,155 text-[#ff9b9b]　② ClientList.tsx:93 #e5484d/#ff9d9f ③ PlanEditor.tsx:414 bg-[#5b1f22] text-[#ffd7d8]（全站唯一滿版）　④ ClientDetail.tsx:145 text-[#d9773f] 橘色

收成兩種：行內錯誤（欄位旁紅字）與區塊錯誤（role="alert" 的紅底 banner，照 PlanEditor 那份做，它本來就做得最完整）。

明顯不一致E6

同一種輸入框存在 10 種寫法，底色 4 種、圓角 3 種、只有部分有 focus

ClientDetail.tsx:49 #0a1a2b rounded-md 無 focus　ClientList.tsx:82 #0d2b45 rounded-md ProfileEditor.tsx:15 #0d2b45 rounded focus:border-[#c99a5b]　SetupWizard.tsx:22 #0a1a28 rounded-lg HomeSwitcher.tsx:49 #12334f rounded-lg　…（共 10 種）

抽 <Field>／<Select> 兩個元件。順便把只有邏輯沒有樣式的 MoneyInput（className="" 預設值）補上預設外觀。

明顯不一致E7

送出中的狀態有三種完整度

護照精靈做到 idle/saving/success/error 四態加轉圈；新增客戶和儲存個人檔案只把文字換成「處理中…」；後台全部只有文字換字，沒有任何 spinner 或骨架。

完整：PassportWizard.tsx:451-459（animate-spin）　只換字：ClientList.tsx:372　ProfileEditor.tsx:306　後台全部

抽一顆 <SubmitButton>，四態一次到位。

明顯不一致E8

危險動作全靠 window.confirm()，而它不吃字級設定

瀏覽器原生對話框套不到產品的深色樣式，也完全不受 --ui-scale 影響——已經開了「特大」字級的老花使用者，看到的確認框還是系統預設大小。這讓老花友善這件事在最關鍵的一步破功。

ClientDetail.tsx:141,178,202　SetupWizard.tsx:80　IntentPicker.tsx:45

用 C2 抽出來的 <Modal> 做一個 <ConfirmDialog> 取代。

細節打磨E9

客戶清單的階段徽章是「連結裡包按鈕」

整列是 <Link>，裡面又放了 <span role="button" tabIndex={0}>，靠 preventDefault 硬攔外層導航。鍵盤使用者在同一個可聚焦區域會遇到兩層衝突的互動語意，也容易誤觸。

ClientList.tsx:173-221（外層 Link）→ :200-222（內層 role="button"）

徽章移出 Link，或整列改成 <div> 內含一個明確的「開啟」連結。

F · 淺色版的地雷

9 項

結論先講：顏色不能反過來，得先有 token 層。沒有 token 就硬做，會出現「有些輸入框還是黑的、所有邊框消失、圖表配色錯亂」，而且沒有任何機制會告訴你漏了哪一個。以下九項是實際會炸的地方。

必炸F1

所有邊框都是半透明白，換成淺底會全部消失

規劃器的 --line 是 rgba(255,255,255,.11)，全檔用了一百多次；Next 端則是 448 處 border-white/N（8 種透明度）。白色疊在淺色底上等於沒有——卡片邊界、表格分隔線、輸入框外框會在同一瞬間全部不見，整個畫面糊成一片。

lantu-app.html:8 --line:rgba(255,255,255,.11)　＋ 33 處 rgba(255,255,255,…) 當進度條軌道／hover 底 Next 端 border-white/5・/8・/10・/12・/15・/20・/25 共 448 處

--line 改成實色 token，兩套主題各給一個值（深色 #1e3d5c／淺色 #dfe4ea）。

必炸F2

已經有一個手工淺色分支，而且它現在就是壞的

規劃器裡有 75 個 dark?'X':'Y' 三元式和 8 處 theme==='light'，是為報表／圖表做的半套淺色。其中生涯藍圖的膠囊在「淺色」分支還是輸出深藍底加白字，坐在一張已經正確變淺的卡片上。一個人漏了一個值，沒有任何東西會抓到。這正是「靠人工維護深淺兩份色碼」的必然結果。

lantu-app.html:11877 CARDBG:'#faf7f1'（卡片已變淺） lantu-app.html:11887 background:'+(dark?'#08252e':'#0d2b45')+';color:#fff（膠囊仍是深底白字）

這 75 個三元式全部改成讀 CSS 變數，讓它們自動跟著主題走，順手修掉這個 bug。

必炸F3

8 種「輸入框深底色」要逐一換掉，而它們本來就已經漏抄過

#0a1a2b／#0a1a28／#0a1a20／#0a2135／#0a2137／#0a2138／#0b2036／#0f2740 全都是同一個語意「比面板再深一階」。既然這 8 個值本來就是複製誤差的產物，人工替換一定會漏，結果就是淺色版裡卡著幾個黑洞。

先合併成一個 --field-bg，再做淺色。順序不能反。

要處理F4

6 個漸層各自寫死兩個深色停點

:16 .top linear-gradient(90deg,#081a2b,#0d2b45)　:174 .report .rc　:178 .hero2 :343 .pcard .phd　:14519 .lnbar　:14651 .ivfab

改成 linear-gradient(90deg,var(--grad-a),var(--grad-b))。

要處理F5

寫死在色塊上的文字色會變成深底深字或淺底淺字

金色膠囊上的 #08202a、深藍膠囊上的 #fff 這類配對現在成立，純粹是有人手動配過。主題一換、底色一動，這些文字色不會跟著走。

:63 .gcard.on{color:#08202a}（金底深字）　:11887 color:#fff（藍底白字） Next 端：26 支檔案用 text-white，同語意的地方又有人用 text-[#eef2f7]

配一組 --on-accent／--on-danger token，文字色永遠跟著底色走。

要處理F6

圖表顏色寫在 inline style 和 SVG 屬性裡，一般掃描抓不到

規劃器有 1,341 個 inline style="…"，圖表的圖例配色（#5b93d6,#5cc08a,#e79ec4,#f0c34e,#ef6f6f）在五個不同的函式裡各複製了一份。Next 端也有 stroke="#0a1a20"、conic-gradient(#2f8f8f …) 這種寫在 SVG 屬性和 style 物件裡的顏色，改 class 完全動不到。

圖例各自複製：:11838 :11864 :11924 :11979 :12073 HomeView.tsx:124,127 stroke="#0a1a20" fill="#a7bacb"　PassportWizard 甜甜圈 conic-gradient

抽一份共用的圖表色盤陣列，兩套主題各一組；SVG 一律改用 currentColor 或 var()。

要處理F7

globals.css 裡那段深色模式是死碼，會誤導人

它定義了 --background／--foreground 和一段 @media (prefers-color-scheme: dark)——但全站沒有任何一頁用這兩個變數（每頁都直接寫 bg-[#081a2b]）。看起來像「深淺主題的基礎建設已經有了」，實際上是 create-next-app 留下來的骨架。

globals.css:19-23 @media (prefers-color-scheme:dark){:root{--background:#0a0a0a;--foreground:#ededed}}

第一步先清掉，換成真正的 token 定義，避免下一個人以為已經處理過。

別忘了F8

分頁工具列顏色鎖死深藍

layout.tsx:33 export const viewport = { themeColor: "#0d2b45" }

改成隨主題切換（或至少不要在淺色版讓瀏覽器 UI 還是深藍）。

別忘了F9

沒有 color-scheme，原生控制項不會跟著換

捲軸、原生 <select> 下拉、日期選擇器、勾選框這些瀏覽器自己畫的東西，不看你的 CSS，只看 color-scheme。缺了它，淺色版會出現深色捲軸配白色頁面。

在兩套主題的 :root 各宣告 color-scheme: dark / light。

建議施工順序

五批

前兩批是地基（淺色版的前置條件），第三批才是淺色版本身，第四五批是美觀修正。每一批都可以獨立上線、獨立回頭。

  1. 把 103 個 hex 收斂成一組語意 token

    建一份 tokens.css：底色三階、文字三階、線一階、品牌兩階、狀態四色、輸入框一階、遮罩一階，約 22 個變數。然後用機械替換把 bg-[#0d2b45] 換成 bg-[var(--panel)]（Tailwind v4 吃得下）。這一步同時把 7 種綠、5 種灰藍、8 種輸入框底色合併掉——也就是把 E1–E6、F1、F3、F5、F7 一次解掉。畫面看起來應該幾乎沒變，這正是驗收標準。

    影響：src 全部 118 支 tsx ＋ 規劃器 CSS 區塊。不動任何邏輯。

  2. 補共用版面殼

    dashboard/layout.tsx、admin/layout.tsx、loading.tsx、error.tsx，加上 <Field>／<Modal>／<ConfirmDialog>／<SubmitButton> 四個共用元件。解掉 A1–A3、A8、C2、D6、E6–E8。

    影響：新增 8 支檔案，改 14 支既有頁面。

  3. 淺色版 ＋ 教練自己切換

    比照現有的字級切換做同一套三重寫入：<html data-theme> 屬性、localStorage（首次繪製前就套上，不閃）、coaches.theme 欄位（換裝置也記得）。規劃器 iframe 走既有的 postMessage 管道，多加一個 lantu:theme。切換鈕放在字級鈕旁邊，後台頭欄也補一份。

    前置：第 1 批。新增一支 migration（下一號是 0036）、一支 lib、一顆元件。

  4. 間距與層次（真正解決「黏在一起」）

    導入三階層次取代滿場 1px 邊框；規劃器的 B1–B6；教練端的 A4–A6；後台的 D1–D4。這批是純視覺，改動範圍大但風險低。

    影響：主要是 CSS 與 className，不動資料流。

  5. 可及性與收尾

    全域 :focus-visible、觸控目標放大、B9–B12、C1、C3、E9。

    影響：小範圍、可零散進行。
