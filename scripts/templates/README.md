# 共用示範範本

所有教練登入後都看得到、誰都改不了的四份示範個案。資料上就是 `clients` 的四列，
只是租戶維度不同：`coach_id = null`、`client_user_id = null`、`is_template = true`
（邊界寫在 `src/lib/clientScope.ts` 的 `templateClient()` 與 `src/lib/templates.ts` 檔頭）。

| 範本 | 主角 | 財務階段 | 這一份要講的事 |
| --- | --- | --- | --- |
| 雙薪育兒家庭 | 林家豪 38 | C 啟程期 | 兩份薪水撐得起現在，撐不起同時到期的學費、換屋與退休 |
| 單身上班族 | 吳宜靜 29 | D 整裝期 | 不是亂花錢，是每筆都剛好，所以什麼都留不下來 |
| 中年企業主 | 張永昌 52 | A 遠行期 | 帳面近億，動得了的現金不到一成；問題在稅與交棒 |
| 屆臨退休 | 黃文彬 60 | B 前行期 | 房子很好、現金不夠，八十歲以後那一段長照接不住 |

四個階段各一份是刻意的：教練示範時要能指著說「你大概在這裡」。

## 怎麼改內容

內容的原始碼是 `cases.ts`，**不是資料庫**。改完一定要走完兩步：

```bash
node scripts/templates/build.mjs      # 1. 過 migrateCase + 實地檢查（會擋下有問題的版本）
npx tsx scripts/templates/seed.ts     # 2. 寫進資料庫（同名的先刪再寫，可重複執行）
```

### 第 1 步為什麼不能跳過

`migrateCase()` 與 `syncPremium()` **只存在於 `public/lantu-app.html`**，`src/lib/engine.ts`
沒有這兩支。直接把 `cases.ts` 的個案寫進資料庫的話：

- 保單表的保費不會投影成支出列 → 每位教練看到的「保費支出比」都是 0%（紅字），而那是假的；
- 健保費那一列不存在 → 年支出少了一筆真實的錢。

`build.mjs` 會用無頭瀏覽器把每一份灌進 `lantu-app.html`（走正式的 `lantu:init` 握手），
走過每一個分頁與子分頁、產一次報告書、截一張分析頁的圖到 `shots/`，
任何一頁是空的、報告書炸掉、或 console 有錯，就不寫 `built.json` 也不讓你往下走。

## 寫這四份個案時踩過的坑

- **所有 `start`／`end` 都是「本人」的年齡**。`projection()` 的時間軸是 `c.profile.age`，
  配偶 60 歲要換算成本人的 62 歲。填成配偶自己的歲數，那筆收入的起訖就整個錯位。
- **購屋目標填自備款，不是總價**。`projection()` 沒有讀 `goals[].loanRatio`（只有 `propertyGaps()` 讀），
  填總價會在那一年一次扣掉兩千多萬，圖直接崩掉。貸款那一段用一列支出表示。
- **孩子不進需求分析表**。`grossLifeNeed()` 會把全部負債與教育金加進**每一位**被保人的
  壽險需求，不分他有沒有在賺錢——照填會讓 3 歲的孩子算出一千四百萬的壽險缺口。
  需求分析問的是「這個人走了，家裡少掉什麼」，答案本來就只有經濟支柱。
- 上面第二、三點都是引擎面的問題，已列入回報；這裡先用本來就正確的填法避開。

## 檔案

- `cases.ts` — 四份個案的內容（唯一真相）
- `dump.ts` — 給 `build.mjs` 用的中繼步驟，不要單獨執行
- `build.mjs` — 過 `migrateCase` ＋ 實地檢查 → `built.json`、`shots/`
- `seed.ts` — 寫進資料庫
- `raw.json` / `built.json` / `shots/` — 產出物，不進版控
